# 犯错记录 2026-09-01

## 日志 f-string 对三元表达式 '--' 应用 :.2f 崩溃，且 0.3s 节流掩盖测试盲区

- **现象**：实机两次转向序列完成后崩溃 `ValueError: Unknown format code 'f' for
  object of type 'str'`（follow_line.py check_rear_trigger 日志行），摄像头已停止。
- **原因**：日志行 `next_at={... if ... else '--':.2f}m` 三元表达式在步骤完成后返回
  字符串 '--'，被 :.2f 格式化 → ValueError。触发路径：process() 内调用
  `check_rear_trigger()` 无 step 前置条件，两次转向完成后仍每帧调用；主循环调用点
  虽有 `_rear_turn_step < len(...)` 条件，process 内没有。
- **修复**：step 完成检查提前到 check_rear_trigger 开头直接短路返回 False；日志行
  去掉 '--' 分支（短路后不可能出现）。
- **预防**：f-string 嵌套三元表达式混用 float/str 时格式代码必须安全；状态机"最终态
  后仍被调用"的路径要先短路再打日志；带节流（0.3s）的日志会掩盖测试中的同类 bug——
  回归测试应主动清零节流时间戳强制走日志分支。

## docker exec bash -lc 长字符串里 pkill -f 匹配自身 argv 导致桥脚本被杀

- **现象**：`run_main_flow2.sh` 停在"starting rear lidar bridge"后无输出；roscore 与
  雷达 roslaunch 已起（/scan 有数据）、:8767 无响应、http 日志仍是旧时间戳、docker
  exec 进程消失。
- **原因**：`run_lidar_rear_bridge.sh` 把整段逻辑塞进
  `docker exec bash -lc "长字符串"`。bash -lc 的 argv 含**外层已展开**的
  `lidar_rear_range_http.py` 完整路径（nohup python3 ${SCRIPT_CT}），执行
  `pkill -f lidar_rear_range_http.py` 时模式匹配到 bash -lc 自身 argv → 杀自己 →
  脚本中止，http 服务未起。（2026-08-08/16/17 "pkill -f 匹配 shell 自身"的又一变体：
  长字符串 + 外层变量展开使 argv 必含目标模式。）
- **修复**：容器内逻辑拆为独立脚本 `lidar_rear_bridge_inner.sh`（docker exec 只
  调 `bash <脚本路径>`，脚本内容不进 argv，pkill -f 不再自匹配）；桥脚本只负责
  docker exec + curl 验证。修复后实测 bridge-ok + rear 有数 + 二次幂等 OK。
- **预防**：凡是 docker exec 里需要 pkill -f 且模式串会出现在命令行里的，把逻辑拆成
  独立脚本文件（argv 只含脚本路径）；不要用 bash -lc 长字符串。另：独立脚本若用
  `set -u`，source ROS setup.bash 前要临时关 -u（catkin profile 引用未定义变量）。

## 测试循环用"输入源耗尽"作退出条件，被测方法最终态短路导致死循环

- **现象**：`tmp/test_rear_trigger.py` 用 `while not h.exhausted`（mock 的
  fetch_rear_range_m 耗尽时置位）作为驱动循环退出条件，运行卡死（timeout 杀掉，
  exit=124）；最小复现显示转向序列触发后循环仍继续到 LOOP GUARD 兜底才停。
- **原因**：被测 `LineDetect.check_rear_trigger()` 在转向序列完成后
  `_rear_turn_done=True`，方法开头短路 `return False`，**不再调用**
  `fetch_rear_range_m()`——输入源永不耗尽 → `exhausted` 永不置位 → 循环死等。
  该短路是生产代码的正确行为（转向后不再处理），问题在测试循环的退出条件设计。
- **修复**：测试循环改为固定迭代次数 `for _ in range(len(seq) + 1)`（len(seq) 次
  消费 rear + 1 次兜底），不再依赖 exhausted 退出；5 个用例全 PASS。
- **预防**：mock 驱动状态机测试时，若被测方法会在最终态短路（不再消费输入），
  不能以"输入源耗尽"作为循环退出条件；用固定迭代次数或"到达终止状态"标志退出。
