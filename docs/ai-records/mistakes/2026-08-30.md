# 2026-08-30 犯错记录

## LCD SPI 并发访问死锁：调参工具与原厂 main.py 抢 SPI，spidev_ioctl 卡死需重启机器

- **现象**：`follow_line_tune.py` 启动后进程卡 `D` 状态（`wchan=spidev_ioctl`），
  8090 一直是 `oumax-camera.service` 推的原始画面（用户误以为部署失败）；`kill`
  `kill -9` 均无效（D 状态信号排队等内核 IO）；同时发现原厂 `main.py`（PID 907）
  也卡在 `spidev_sync_write`，`systemctl stop raicom-original-main` 超时 failed。
- **原因**：LCD（xgoscreen）走 SPI 总线 `/dev/spidev0.0`。`raicom-original-main.service`
  常驻跑原厂 main.py 刷新 LCD；调参工具只停了 `oumax-camera.service`（计划漏了
  SPI），初始化 `LCD_2inch()` 时与原厂 main.py **并发传输 SPI 导致控制器挂起**，
  两个进程的内核 ioctl 都不返回 → 双双 D 状态，唯一恢复手段是重启机器。
- **修复**：①重启机器（SPI 控制器状态复位）；②两个工具（`follow_line_tune.py`、
  `yolo_view.py`）启动时改为**同时停 `raicom-original-main` + `oumax-camera` 两个
  服务**（记录启动前状态，退出按原状恢复），与 8-16 巡线"停 raicom-original-main
  + oumax-camera 释放串口/相机"的完整前置一致。
- **预防**：**凡初始化 LCD（xgoscreen）或使用 SPI 的工具，必须先停
  `raicom-original-main.service`**，只停相机不够；厂商程序前置条件一律按
  lingo「巡线」词条的完整两服务停用；排查 8090 显示"原画面"时先
  `ps -o stat,wchan -p <pid>` 看是否 D 状态卡在 spidev_ioctl，再查
  `fuser /dev/spidev0.0` 谁占 SPI。
