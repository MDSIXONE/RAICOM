# 犯错记录 2026-08-13

## 左后轮当前无法驱动，与 2026-08-11 四轮均可驱动结论冲突

- **现象**：单轮驱动实测（kind=wheel、速度 1.2、10Hz 持续刷新 20 秒、200 次命令均 ACK ok）：左前轮（通道0）转动正常，左后轮（通道3）现场观察无转动。
- **原因**：未定。与 2026-08-11 记录“四轮均转动”冲突，可能为左后轮电机/驱动板/接线故障或连接松脱，也可能为轮控通道映射或固件状态变化；命令 ACK 只能证明服务端执行，不能证明实际转动（延续 08-11 预防条款）。
- **修复**：无软件修复。需现场检查左后轮电机、驱动板与接线；软件侧已排除通道映射（通道顺序 [左前, 右前, 右后, 左后]，左后=索引3）与刷新频率问题（10Hz 与 ball_align 标定一致）。
- **预防**：硬件驱动能力结论每次实测都必须以现场观察为准，不能直接复用历史结论；单轮诊断命令 ACK 通过 ≠ 轮子实际转动。

## curl 单请求循环未达到 10Hz 轮控刷新

- **现象**：PowerShell 以 `curl.exe` 同步逐请求发送 20 秒左后轮单轮指令，仅完成 127 次成功 ACK，平均约 6.3Hz。
- **原因**：每次 HTTP 请求建立/处理的同步开销超过 100ms；在请求完成后再固定等待 100ms 会进一步降低有效刷新率。
- **修复**：本次已在结束后显式发送零速停止；若后续必须严格 10Hz，应使用复用连接的客户端或将发送节拍按单次请求耗时补偿。
- **预防**：涉及“10Hz 持续刷新”的实机轮控测试，结束后必须报告实际成功请求数和有效频率，不能只按循环 sleep 设想频率。
