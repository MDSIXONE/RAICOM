# 犯错记录 2026-08-14

## 低趴车体指令会复位机械臂接球姿态

- **现象**：机械臂已处于接球姿态时再发送 `translation('z', 10)`、`attitude('p', 15)` 低趴命令，机械臂随即复位，无法保持接球位。
- **原因**：该机固件的车体姿态控制会覆盖或重置机械臂当前保持姿态。
- **修复**：抓球准备必须固定为“先低趴车体 → 再完整下发机械臂接球序列（爪子、小臂、大臂、小臂）”。
- **预防**：今后任何“趴下后接球/抓球”指令都不得先摆机械臂；若车体姿态被重新下发，必须再次下发机械臂姿态。

## xgomini xgolib 将大臂 53 的 +120 钳制为 +90

- **现象**：厂商抓球脚本与自定义程序均向 53 号大臂发送 `+120`，容易被误认为大臂可实际达到 120°。
- **原因**：机器实际厂商运行库 `xgolib_dog.py` 选择 `xgomini` 参数，`MOTOR_LIMIT[5]` 为 `[-75,90]`；`conver2u8` 对超过上限的数据直接输出 `0xFF`，即代表 +90。
- **修复**：把文档中的上限表述修正为实际 +90；后续控制代码应直接写 +90，避免伪精度。通过 HTTP 手控服务的 53 上限 100 与运行库不一致，仍会在运行库侧钳到 +90。
- **预防**：电机角度上限以机器实际选中的 xgolib 机型分支为准，不能只依据调用脚本中的数值或上层服务的校验范围。

## 机械臂安全顺序：大臂 53 前必须先抬小臂 52

- **现象**：用户确认大臂直接动作存在与摄像头、地面或自身机构干涉的风险。
- **原因**：大臂驱动时，若小臂仍处于低位或不安全位置，爪端轨迹不可控。
- **修复**：任何大臂 53 指令前，先发送小臂 52 的安全抬起/避让命令，确认后才允许发送大臂指令。
- **预防**：所有抓球、复位、姿态微调脚本都必须把“先小臂、后大臂”作为不可跳过的执行顺序。

## xgomini xgolib read_motor 读取 15 舵机反馈触发 IndexError

- **现象**：调用机器厂商运行库 `dog.read_motor()` 读取当前关节角度时抛出 `IndexError: list index out of range`。
- **原因**：`xgolib_dog.py` 的 `read_motor` 对接收数组索引 `i - 9` 缺少与 `MOTOR_LIMIT` 长度的边界匹配，读取到 15 个电机数据时访问越界。
- **修复**：当前不依赖该接口读取实时姿态，后肢微调以已下发的抓球趴伏基准角为起点；如需可靠反馈，需单独修复/替换厂商库解析逻辑。
- **预防**：不要把 `read_motor()` 当作实机姿态闭环反馈来源，先以单独测试验证其返回长度与 15 个舵机限幅表一致。

## SSH stdout BrokenPipeError 终止长时抓球程序

- **现象**：通过有超时的前台 SSH 直接运行持续抓球程序时，本机超时关闭 stdout 管道，远端 Python 在下一次 `print(..., flush=True)` 抛出 `BrokenPipeError` 后退出。
- **原因**：抓球进程的标准输出依附 SSH 会话；会话被本机执行超时终止后，远端写入已关闭的管道。
- **修复**：持续实机流程用 `setsid` 后台启动，输出重定向到机器端独立日志，再通过短时 SSH 读取 PID、进程和日志。
- **预防**：不要以有固定本机超时的前台 SSH 作为长时硬件程序的宿主；需要持续监控时将控制进程与观测会话分离。

## xgolib motor 列表接口不是原子多舵机同步

- **现象**：将后肢写为 `dog.motor([31, 41], [26, 25])` 后，曾误判为同一控制包同步抬起。
- **原因**：实际 `XGO_DOG.motor` 遍历列表，并对每个 ID 调用 `__motor`；`__motor` 各自调用 `__send("MOTOR_ANGLE", index)`。
- **修复**：更正操作记录与代码改动记录：该写法仅去除了显式延时，仍为连续两帧，不能承诺物理同步。
- **预防**：声称“同步”前必须检查运行库的实际序列化与发包实现；列表 API 不等于总线原子批量命令。
