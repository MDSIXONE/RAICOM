# 犯错记录 2026-08-31

## 左后轮通道3 复测仍不转（ACK ok，+1.2/+1.5/-1.5 均无现场转动）

- **现象**：`drive_wheels_sequential.py` 四轮依次各 7s@1.2：左前/右前/右后现场转动，左后（通道3）不转；随后单测左后 +1.5 与 -1.5 各 5s 命令全 ACK ok，左前对照 +1.2 正常。
- **原因**：与 2026-08-13 一致，倾向硬件（电机/驱动板/接线/固件通道失效），非软件映射——同会话同 API 下通道 0/1/2 均可转，排除通道顺序、刷新频率、手控服务与 enable_wheel 路径问题。
- **修复**：无软件修复。需现场查左后轮电机、线束、驱动板；导航/运动继续以 foot 为主，勿假设四轮差速可用。
- **预防**：轮控能力以当次现场目视为准；ACK≠转动；左后轮故障为持续状态，勿因历史“四轮均可”（08-11）或“仅左侧有驱”（08-08）直接复用旧结论。

## roslaunch $(eval arg()) 先使用后定义：requires the 'odom_mode' arg to be set

- **现象**：在 `robot_dog_main.launch` 的 gmapping 分支 `<group if="$(eval arg('enable_mapping') and arg('odom_mode') != 'carto')">` 里引用 `odom_mode`，`roslaunch --nodes` 报错 `requires the 'odom_mode' arg to be set`，该模式节点集为空/解析失败。
- **原因**：roslaunch 的 `<arg>` 定义是**顺序敏感**的（类似变量先声明后使用）。`odom_mode` arg 原本定义在文件第 68 行，而 gmapping 分支在第 32 行——group 的 `if/unless` eval 在解析时立即求值，引用了尚未定义的 arg。
- **修复**：把 `odom_mode` 与 `use_amcl` 的 `<arg>` 定义整体移到 `enable_mapping` arg 之后、gmapping 分支之前（launch 文件前部）。
- **预防**：在 launch 的任何 `$(eval arg(...))` / `$(arg ...)` 引用前，先确认对应 `<arg>` 定义位于文件更靠前的位置；新增引用时优先把 arg 定义集中在文件头部。

## Cartographer num_subdivisions_per_laser_scan 时间戳坑

- **现象**：carto 建图时 `/map` 只有 ~1 帧的障碍点、无空闲区域（建图停滞）；
  日志反复 "Ignored subdivision of a LaserScan message ... previous subdivision
  time ... is not before current subdivision time"（两个时间完全相同）。
- **原因**：ydlidar scan 的点无 per-point 时间偏移，cartographer 把每帧 scan
  细分（num_subdivisions=10）后，段间 subdivision 时间恒等，被 sensor bridge
  判为“时间不前进”而忽略大部分 scan。
- **修复**：`num_subdivisions_per_laser_scan=1`（合法最小值 = 整帧一段不细分，
  跨帧按 header.stamp 比较正常推进）；注意 **=0 会让 cartographer 1.0.0
  CHECK 崩溃**（trajectory_options.cc:30 `>= 1`）。实测 subdivision 警告消失、
  /map 正常累积空闲/障碍。
- **预防**：改 cartographer 配置先看版本约束（1.0.0 要求 >=1）；scan 数据源
  无 per-point 时间时，subdivision 必须=1；建图停滞时先查 submap_list 是否
  增长、/map 是否含空闲(0)与障碍(100)，而不是只看点云。

## Cartographer 建图分支的节点条件设计

- **现象**：原 launch 中 `odom_mode:=carto` 分支整体被 `<group unless="$(arg enable_mapping)">` 包裹，导致 `enable_mapping:=true` 时 cartographer 根本不会启动——无法用 Cartographer 建图。
- **原因**：carto 分支是为"定位模式"添加的，挂在定位 group 下；mapping 时定位 group 整体排除，carto 分支跟着被排除。
- **修复**：把 carto 分支从定位 group（`unless enable_mapping`）中移出为独立 group（`if odom_mode == 'carto'`），并给 gmapping 分支加 `odom_mode != 'carto'` 互斥条件；`odom_mode`/`use_amcl` arg 定义前移。五种模式节点集验证通过（定位 carto/建图 carto/建图 gmapping/定位 amcl/定位 cmd_vel）。
- **预防**：launch 里新增分支时先梳理 group 嵌套与条件互斥关系，用 `roslaunch --nodes` 对每种参数组合做节点集验证，而不是只验证默认组合。
